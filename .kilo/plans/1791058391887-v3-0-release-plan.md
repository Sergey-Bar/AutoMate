# Automate v3.0.0 — the install runs the tools

**Baseline:** `package.json:3` = `2.2.0`. `CHANGELOG.md:5` already carries
`## Unreleased — v3.0 groundwork` (RF-5 back to `open`/`Blocker`, `docs/quality/wave-gates.json`,
the RF-6 row). Ledger: 153 rows — 6 `open` (C-4, RF-5, RF-9, RF-11, PERF-1, RF-6d), 7 `debt`
(X-3, D-4, C-6, UI-1, Q-1, CAP-1, SITE-1). Register: 42 rows — 16 `real`, 14 `mock`, 2 `missing`,
8 `deferred`, 2 `obsolete`.

The plan of record for v3.0 (`.kilo/plans/1790920670956-five-major-versions-ponytail.md`) is
**"the install works"**: real runner images, durable control plane, durable inventory, isolated
Playwright, then a tag. This plan keeps that thesis, pulls the two `missing` capabilities into it
(D1), and deletes a large part of it, because re-reading the tree shows most of the work is already
built and the register is what is out of date.

**Load-bearing decisions must land in a tracked artifact.** `.git/info/exclude:9` excludes `.kilo/`;
`git ls-files .kilo` returns exactly one file. Task 0.1 fixes that. Every other decision below is
encoded as a JSON field, a gate assertion, or a ledger row — never as a sentence in this file.

## 1. Bug fixes — categorised

### 1.1 The register is wrong about three rows (record defects)

`tool.k6` says *"No k6 parser, threshold model, or isolated image exists"*; `packages/reporter/src/adapters/k6-json.ts` (285 lines) and `adapters/zap-xml.ts` (216 lines) exist, are exported at `packages/reporter/src/index.ts:33-34`, and are covered by `k6-json.test.ts`, `zap-xml.test.ts`, `new-adapter-parity.test.ts`, `adapter-edges.test.ts`. `tool.zap` says the same. `automation.agents` says *"Agent endpoints return static completed outputs"*; `apps/api/src/routes/agents.ts:93-101` answers an explicit `501 AGENT_NOT_CONFIGURED` for every domain/action pair. `reporting.lifecycle` names only Playwright/JUnit.

- Re-derive the four rows against the tree; correct status, qualification and evidence.
- Rows stay `missing`/`mock` here — the *image* is what is absent (3.5), and a row is `real` only when the thing runs.
- Give `tool.k6`/`tool.zap` a `command` cell now (`pnpm --filter @automate/reporter test`), which is `CAP-1`'s unblocked half and the cheapest way the next stale row is caught by a gate rather than by a release.
- **New ledger row** for the class: *a register row whose status was asserted against a tree that had since moved*. Provenance `hand`, band Major.

### 1.2 The upload door cannot ingest the two formats it has adapters for

`apps/api/src/routes/reporter.ts:199-230`: `pickAdapter()` reaches `junitXmlAdapter`, `playwrightJsonAdapter`, `legacyUploadAdapter`. `declaredFormat()` returns `'junit' | 'playwright' | ''`. Consequences today: a k6 summary is JSON with no recognised spelling → routed to the legacy upload adapter; a ZAP report is XML → `looksLikeXml()` → the **JUnit** adapter, which then reports *"JUnit report contains no test cases"* about a security scan. `ProvenanceSchema.producer` (`packages/shared-contracts/src/schemas/canonical-reporting.ts:115-125`) already lists `k6`, `zap`, `robot`, `otel`, `sarif`.

- Extend `declaredFormat()` with `k6`/`k6-json`/`k6-summary` and `zap`/`zap-xml`; `pickAdapter()` selects `K6_JSON_ADAPTER` / `ZAP_XML_ADAPTER`.
- `assertFormatMatches()`: `k6-json` must be JSON, `zap-xml` must be XML — refusals name the spelling to use, matching the existing message style.
- Red-first: write the four cases (k6 JSON, ZAP XML, both mislabelled in both directions), run them against the current code, watch them fail for the reason above, then fix.
- One format vocabulary: `RESULT_FORMATS` (`packages/projects/src/detect/types.ts:46`), `artifactKind()` (`apps/runner/src/generic-spawn.ts:467-476`), `declaredFormat()` and the producer enum are four spellings. Make the contract the table the other three read.

### 1.3 A control that cannot be true

`runners/*/manifest.json` declare `network: "none"`, asserted at `scripts/oci-checks.mjs:132` and `scripts/lib/oci-images.test.mjs:124` / `oci-checks.test.mjs:39,157`. All three tools need to reach a target.

- `network` becomes `{ "mode": "none" }` or `{ "mode": "target", "allow": ["<origin-or-$ENV>"] }`.
- `oci-checks.mjs` fails a missing policy, a policy wider than the tool needs, and a `target` policy that does not name what it targets. Move both assertions to the same commit, with the reasons in `scripts/gate-tooling.json`.

### 1.4 The production API cannot list, cancel, schedule or automate anything

`apps/api/src/index.ts:285-293` 503s `/api/v1/automations*`, `/api/v1/schedules`, `/api/v1/jobs`,
`/api/v1/jobs/*`. The durable runner callbacks (`/api/v1/jobs/:jobId/{events,artifacts,complete}`,
`apps/api/src/routes/execution/jobs.routes.ts:94-164`) are mounted at `index.ts:526-598`, **before**
`mountLegacyProcessLocalRoutes()` at `index.ts:600`, so Hono resolves them first and the runner is
not broken. **Name that trap in the changelog**: the wildcard reads as a production outage and is not.

What is genuinely missing in production is a durable **cancel** and a durable **job list** — the only
two the 503 actually catches — plus the whole process-local surface, which nothing in `apps/web/src`
calls.

- Add `POST /api/v1/jobs/:id/cancel` to the execution module: lease-fenced, workspace-scoped,
  terminal-state transition through the same store the completion path uses.
- Add `GET /api/v1/jobs` **bounded** (page + cursor, like `runs.routes.ts:65-68`). An unbounded list
  on a GET route is the recorded `SEM-4` class; do not recreate it.
- Isolation test for both, cross-workspace, per `AGENTS.md`.

### 1.5 An `open` ledger row the tree refutes

`RF-6d` (ledger line 3419, `open`, W2) states the worker→runner path "is dormant in production today"

- **New row** for the half that is real: W2's gate — *a job runs worker→runner on PostgreSQL, proven

  this is an addition, not a re-label.

## 4. Hardening

1. **Isolation that is real** (D3): uid `65532`, `no-new-privileges`, `CAP_DROP`, read-only root,
   bounded `resources` from the manifest, and a network policy that names its target. Asserted
   against the built image, not the JSON that declares it — the rule `oci-checks.mjs` already
   applies to `user`/`readOnly`.
2. **No container socket, ever.** Recorded in the ledger row for `runner.oci` with the reason, so a
   later reader who wants `docker run` has to argue with the recorded decision rather than add a
   mount.
3. **Tier raise with its evidence, in one commit.** `security:static` → `pr-blocking`
   (`scripts/gate-tooling.json:64`). The evidence exists and is dated: zero findings, semgrep
   1.178.0, run `36962862652` (`CHANGELOG.md:78-79`). Standing rule 2 — evidence then raise, never
   raise alone. `test:e2e` is already `pr-blocking` (`:73`); nothing to do.
4. **Refusals name the fix.** A ZAP report must never reach the JUnit adapter; a k6 summary must
   never reach the legacy adapter; a `format=` this build does not read must be refused by name, the
   way `assertFormatMatches` already refuses an XML body declared as Playwright.
5. **No silent fallback anywhere in the new path**: exit code + declared artifact decide status
   (`generic-spawn.ts:441-456`). A run that produced no declared artifact is `infra_failed`, never a
   pass. `E2E_ALLOW_IN_MEMORY` stays out of v3.0 scope and out of every release run.
6. **No secret in an image.** `RUNNER_REGISTRATION_SECRET` arrives from the environment as it does
   today; `oci:verify` asserts each Dockerfile ends on its declared uid and never on `USER root`
   (`scripts/lib/oci-images.test.mjs`).
7. **RF-11, cheap and load-bearing now**: v3.0 changes the contract's format vocabulary, so a spec
   generated by hand from the old one would be wrong immediately. Emit from
   `@asteasolutions/zod-to-openapi` (already a `shared-contracts` dependency) inside
   `docs:capability-register`, and fail `docs:check` on divergence. Reword BK-5's entry criterion to
   name the gate.
8. **CAP-1**: the `command` column lands for the rows v3.0 moves. `scripts/lib/docs-drift.mjs`
   already refuses a `pnpm …` citation that is not a root script and is already in `docs:check`, so
   this half needs the column and nothing else.

## Risks

- **The images are the long pole.** A Playwright browser in a build is large and slow. If
  `oci:build` does not fit a CI job, it stays tier `release` (`gate-tooling.json:87`) and builds on
  the release host — recorded, not lowered.
- **Phase 3 changes the enrolment contract.** Task 11 is what stops an old runner from
  mis-registering against the new shape.
- **The rehearsal is the release's real risk** (D2): it needs a second database, the PostgreSQL
  client tools, and a sealed row. Anything missing means the tag waits, not that the claim softens.
- **Deleting the process-local surface is the breaking change** — `/api/v1/runner/v1/*`,
  `/api/v1/automations*`, `/api/v1/schedules`, `GET /api/v1/jobs`,
  `POST /api/v1/automations/:id/jobs`, `POST /api/v1/jobs/:id/cancel`. It belongs in the release
  headline, and the two runner callback families that survive must be named there too, because the
  503 wildcard made them look like casualties.
- **Register churn is the failure mode of this release**: 12 rows change. If a row cannot be
  re-derived from the tree in this release, it stays as it is and is named in the notes.
