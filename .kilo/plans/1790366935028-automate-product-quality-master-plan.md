## 3. Track structure and the interlock rule

- **Track Q (quality spine)** — Q0 → Q5. Q0/Q1 land before any product wave merges. Q2–Q5 run continuously.
- **Track P (product capability)** — P0 → P5. Each wave is a gate: a clean checkout must reproduce it.
- **Interlock:** a P-wave may not merge with a red Q gate. Each completed P-wave raises the Q floor for the next (ratchet numbers only go up).
- **Wave size:** keep every PR inside the review budget in Q2 (≤400 changed lines; ≤800 requires a written justification in the PR body). Large refactors are split into mechanical steps so the reviewer stays useful.

## 4. Track Q — Quality spine, hygiene, review, verification

### Q0 — Baseline truth and broken-gate repair (blocks everything)

Q0 runs as ten ordered sub-waves. Q0.10–Q0.19 exist because the three code-review passes (§11, §12, §14) found exploitable defects, integrity defects, and product bugs that must not wait for the product waves. Each sub-wave lands with its own regression tests; Q0.10 (security) goes first.

**Q0.1–Q0.9 — baseline and gate repair**

1. **DONE — gates are now standard, not 100%.** Per-package `coverage.thresholds` measured the real number: `apps/worker` 57%, `packages/db` 31%, `packages/ui` 62%, `tools/migrate-cli` 78%, the connectors 10–82%. Enforcing 90/80 as a per-package threshold would fail four packages on every `pnpm test --coverage` run, and a gate that blocks all progress gets raised until it means nothing. So the floors live in **one** place — `scripts/coverage-ratchet.mjs` against each package's recorded value in `coverage-baseline.json` — and `vitest.shared.ts` supplies measurement config only (`all: true` + explicit `include`, the part that was actually broken). `packages/shared-contracts` dropped its 100% claim: once it was genuinely measured it was 99.59/97.69, and it now carries the standard 95/90 floor. 19 of 22 packages are ratcheted on measured numbers; 3 are honestly `not_configured` (`apps/runner` has two pre-existing failing tests, `tests/contract` and `tests/integration` have no source files) and are *reported* as such rather than counted as passing. The ratchet derives its package set from the workspace and fails if it and the baseline disagree in either direction.

   **A floor that measured the wrong thing — found and closed.** A schema change dropped `packages/db` to 60.98 statements against a recorded floor of 61, and the cause was not the change: all three of that package's repositories were reported at **0%** by its own coverage run. They *were* covered — `tests/integration` drives `DrizzleSessionStore` and `DrizzleInstallationKeyStore` end to end — but that coverage is measured in another package, so the number the ratchet read for `packages/db` did not describe `packages/db`. A real test contributing nothing where the measurement happens is the same shape as a gate measuring nothing while printing a number, which item 3 is about. `packages/db/src/repositories/repositories.test.ts` now runs the same assertions **inside the package that owns the code**, on the real migration graph, covering the session lifecycle (valid → expired → revoked, and a second revocation reporting honestly false), installation-key bootstrap not rotating, and the outbox's workspace scoping, cursor, dedupe, expiry filter, validation-before-write, purge and retention floor. `packages/db` statements went 60.98 → **75.75** and the repositories are at 100%, with the floor untouched. Writing that test also produced a failing assertion worth having: the page-size clamp test initially asserted against a workspace it had not written to, which is the same class of mistake the assertion is meant to catch.
2. Add a `coverage` block to every `vitest.config.ts` that lacks one — **DONE** (all 22 use `standardCoverage`), and add `packages/connectors/*/vitest.config.ts` to the root `projects` list so `pnpm test` at the root actually runs them.
3. **The exclusion is now measured, and measuring it found a live defect.** `docs/quality/coverage-exclusions.md` carried `src/execution/drizzle-execution-store.ts` as "the largest file in the repository — excluded rather than measured", which is a claim, and the plan's own B4 row said the removal condition was "the shared scenario suite runs against both stores". Measuring it is the thing that says whether either is true.

   **Measured, with the exclusion lifted: 76.11% statements, 71.77% functions, 58.48% branches** — not 0%. The PGlite suites already drive most of the file; lifting the exclusion drops `apps/api` from **93.95 → 91.52** statements and **84.71 → 79.42** branches, just under the 93/80 floors. So the exclusion stays, and the register now carries the number and the named gap instead of a shrug: `getReadiness`, the `mapRuns` batch loader, and the runner lifecycle.

   **Measuring it found that finding 45 was never fixed, and the plan had marked it stale for the wrong reason.** The plan recorded `authenticateRunner`'s table scan as "**stale**, because `runners.token_hash` is already uniquely indexed, so runner authentication was never a sequential scan". The index existed. The **query never used it**: `authenticateRunner` read *every row in `runners`* and compared hashes in a JavaScript loop, so every authenticated request paid a full table read whose cost grew with the number of runners enrolled. The conclusion was drawn from the schema instead of from the code, and the schema was the one thing that could not show the problem. It is now one indexed lookup, with the two refusals — revoked, expired — pushed into the same `WHERE` so rows are not transferred only to be discarded, and `limit(2)` rather than `limit(1)` because the column is not declared unique. The constant-time comparison is kept per candidate on purpose: pushing equality into SQL would be index-served and fast, and would also make the token's hash a timing oracle, which is the one thing hashing it was for.

   `runner-lifecycle.drizzle.test.ts` (13) covers that path on the real migration graph, one workspace per test: the right token authenticates; a wrong token, a **prefix** of the right one, an empty token, a revoked runner and an expired token do not; a re-enrolment leaves one row and makes the *new* token the live one; `runners_health_check` refuses a value outside its vocabulary; a runner whose capabilities and labels do not match the job claims nothing; an append without the lease, and one with a stale fencing token, are both **conflict**; the holder's own append is **accepted**, so the two refusals are refusals and not a closed door; and a swept lease has its `lease_id` cleared rather than merely its state moved, because a released job that still names its holder is a split-brain with no detection.

   **A cross-workspace question this could not answer, recorded rather than guessed.** `reapExpiredLeases` builds its predicate from `state` and `lease_expires_at` only — there is no workspace clause, while every other method in the file scopes by the `workspaceId` the store was constructed with. Two readings: the reaper is deliberately global (one process owns every runner, and scoping it would let one workspace's jobs wait indefinitely), or the scope was forgotten. What settles it is whether the outbox event a reaped job appends names the *job's* workspace or the *store's*. A test keeps the question attached to the code and fails **only** if the predicate later gains a workspace clause — so if someone does scope it, the note cannot outlive the code.

   **What is left, honestly:** `getReadiness` and the `mapRuns` batch loader are the remaining named gap, and the exclusion goes when the file itself measures at or above the floor. The register says so with a removal condition that names a thing which could happen.
4. **DONE — the format globs, and the 22 files they were silently skipping.** `format` and `format:check` were twenty hand-written globs, one per directory shape, and nothing failed when a directory was added: the new files were outside the list, so they were never formatted and never checked, and `format:check` stayed green. That is a gate reporting success about a set it is silently not looking at. Audited against a whole-tree glob, the list missed **22** files — twelve `.github/agents/*.md` definitions, two package READMEs, a design map, the six drizzle metadata files, and **the whole `performance/` directory** the Q0.18 k6 gate introduced, which means the formatting gate was not checking the performance gate's own scenario and thresholds.

   Three globs now, and `.prettierignore` is the exclusion mechanism: every source extension anywhere, every data/config/prose/style extension anywhere, and `.github/workflows/*` kept only for its own `.prettierrc` override. **A glob that names no directory cannot fall behind a new one**, which is the whole point.

   The six drizzle metadata files are excluded *explicitly*, and that is the part worth stating: they are generated, and formatting them makes `db:generate` show a diff nobody made. The old list never had to say so, because it omitted `packages/db/drizzle/**` entirely — the exclusion was real and silent, which is the worst shape for one.

   **What stops it drifting again, and what that gate does and does not prove.** `tests/contract/format-glob-coverage.test.mjs` (6) enumerates the **tracked** file list with `git ls-files`, converts the format globs to matchers, and fails if any file prettier would format is not reached — so "the globs are broad" is replaced by an actual comparison, and the twenty-two previously-invisible files are named one by one. It also fails if the globs are optimised back into a directory list, and if `.prettierignore` grows a bare `*`, which would switch the gate off while it still printed "checked".

   Two honest limits. The glob→regex conversion supports only the forms the scripts use and **throws** on anything else rather than guessing, because a gate that mis-reads its own patterns reports success about a set it never computed. And the comparison is against *tracked* files, so a file that exists only on this machine is outside its opinion — correct, since the gate cannot be expected to have an opinion about an uncommitted file.

   **A fourth assertion was written, failed, and was removed.** It asserted "no tracked file is unformatted" — which `format:check` already does, authoritatively, three steps earlier. Run inside the contract suite it read the *live filesystem* while twenty package suites were generating files, and it failed on a transient artefact of that concurrency: a gate depending on another process's state, which is the same mistake it exists to catch. `format:check` owns "is anything unformatted"; this gate owns "does the gate look at everything". Two owners for one property is how one of them ends up measuring something it does not control. The suite now runs in **358 ms** instead of 38 s, because the two `npx prettier` subprocesses are gone.

   **Proven fail-before:** narrowing `format:check` back to a directory-shaped glob fails it with `names a directory shape, so a new directory is skipped`. And the gate's own first run **failed** on itself — it reported the test file as unformatted, which is the correct verdict and the reason the bootstrap needs one `pnpm format`.
5. **DONE** — `scripts/license-check.mjs` derives the workspace list from the tree (22 packages, up from a hand-kept 18 that omitted `packages/config`, `apps/worker`, `tests/contract`, `tests/integration`) and fails if the derivation finds nothing. `--failOn` now includes `UNLICENSED;UNKNOWN`, because this repo's own packages declare `UNLICENSED` and an undetectable licence is an unknown one, not a non-issue. Deny-list report for GPL/AGPL/SSPL with the k6 decision still to record.
6. **DONE** — `scripts/performance-gate.mjs` no longer ends its success branch in `process.exit(1)`. It has three honest outcomes: pass (k6 ran the committed scenario and every threshold held), fail (a threshold was breached, or the scenario and the recorded thresholds disagree), `not_configured` (no k6 installed). `not_configured` exits non-zero — a performance claim needs a measurement — and says which parts of the gate *did* run. The committed scenario and thresholds are in Q0.18 item 8.
7. **DONE** — `scripts/oci-verify.mjs` now uses the container runtime: it detects docker or podman (the build script hardcoded podman), inspects the real image, requires `buildStatus: "built"`, requires a built sha256 digest, and cross-checks the recorded digest against the runtime's. A missing manifest is a failure, not a `readFileSync` stack trace. No runtime → `not_configured`, non-zero. All three manifests still carry `"imageDigest": null`, so the gate reports that honestly.
8. **DONE** — `scripts/unify-preflight.mjs` asserts the workflow set exists *before* checking its contents, so "Actions are SHA-pinned" and "workflows use the root Playwright command" can no longer pass on an absent or empty `.github/workflows`; a new "every preflight input was readable" check reports which inputs it could not read. Both directory walks now share one `IGNORED_DIRECTORIES` set, so the first step of `pnpm verify` no longer descends into `.git`, `.turbo`, `.omo`, `.sisyphus`, `playwright-report`, `var` or `blob-report`. `scripts/coverage-ratchet.mjs`, `scripts/license-check.mjs`, `scripts/migration-rehearsal.mjs` (report field renamed to `plannedPhases` + `rehearsalPerformed: false`, and the script now says so) are repaired. `scripts/disabled-tests.mjs` is one shared definition of a disabled test, used by both the ESLint rule and the preflight — the old rule matched only `.skip`/`.only` and missed `xdescribe`, `xit`, `test.todo`, `test.skipIf`, `test.runIf` and `test.fails`.
9. **DONE** — `pnpm quality:baseline` (`scripts/quality-baseline.mjs`) prints the current status of every gate in one report, so the baseline is reproducible rather than remembered. It measures everything at run time and reports a gate that cannot run as `not_configured` rather than as a pass: tests, the coverage ratchet (with the three unconfigured packages named), duplication, complexity, the static-analysis config check, the secret scan and its self-test, preflight, and the four external tools (semgrep, gitleaks, k6, a container runtime — this host has **docker**). **Product call:** the report exits non-zero on a *failure* but not on `not_configured`, because on a solo maintainer's machine the external scanners and the container runtime are routinely absent and a report that is always red is one nobody reads; the `not_configured` rows are printed prominently for exactly that reason. Building it found four bugs in itself, which is the argument for having written it: a hardcoded `node_modules/jscpd` path that does not exist under pnpm's store layout, a "last line" heuristic that reported `coverage:ratchet`'s status as `- tests/integration`, a mislabelled test count, and — worst of them — a line that took the *name* of one package and the *figure* of another, reporting `apps/api at 10%` when 10% is `packages/connectors/github` and `apps/api` is 93%.

   **A gate that failed for the wrong reason — found twice by running it, and the same shape both times.** A timeout budget that did not describe the work.

   - **`tests/integration` was red.** Two files applied the real migration graph to PGlite in parallel, each `beforeAll` crossed Vitest's 10s default, and the run died with **14 passed / 13 skipped** — the skipped thirteen being exactly the assertions about the migration graph. `fileParallelism: false` is the fix, not a bigger timeout: the files were competing for the same cores while each held a Postgres WASM heap, so serialising them is *faster* and deterministic (27/27 in 8.7s, against 25s with 13 skipped). `hookTimeout` then only has to cover one file's real work rather than a contention worst case.
   - **`refuses to compose without a cookie secret` failed under `pnpm verify`** while passing four times out of four in isolation. It imports the entire API graph for the first time — about **2 s unloaded, measured at 37 s** with turbo running twenty package suites in parallel — and blew the package's 30s `testTimeout`. A test whose subject is a fail-closed startup policy reported a failure that had nothing to do with the policy, and the only honest response to such a gate is to stop trusting it. The file now sets its own budget with `vi.setConfig` and restores the package default in `afterAll`; the package default stays right for the PGlite suites. 120 s is headroom, not a target, and it is scoped to the one file that needs it rather than loosened everywhere.

   A third option was considered and **rejected**: a custom Vitest reporter failing any run that contains a skipped test. It was built, and then deleted. Vitest 4's reporter callbacks are undocumented at this version — `onFinished` never fires on a failing run, and `onTestFinished` never fires for a suite whose `beforeAll` threw — so it would have been written by guessing at payload shapes. A declared `.skip` is already caught by the ESLint rule and `unify-preflight`, and a hook timeout *does* fail the run, so there was no real silent-pass gap left to close, only a fragile gate to add. A gate built on guessed APIs is worse than no gate, because it looks like coverage.

   - **A fourth, and the one that actually explained a red suite: `node --test`'s default parallelism.** `pnpm test:integration` runs four `scripts/lib/*.test.mjs` suites, and it was failing **33/36** — three assertions from `gate-tooling.test.mjs`'s "the committed workflows are wired correctly", reporting eight CI-wiring findings that are *not there*: every workflow **does** have a `concurrency` block, **does** install k6, **does** declare `services:`, and `unified-ci.yml` explicitly does **not** set `E2E_ALLOW_IN_MEMORY`. Run the four files **serially** and it is **36/36**; run each file alone and every one passes. So the audit was reading a repository in a state that did not exist — four independent audit-style suites contending, one of them observing another's fixture.

     The fix is `--test-concurrency=1`, which costs about a second on 36 tests. **The residual is stated rather than papered over:** I established the interference and the fix, but I did **not** identify *which* shared state is contended — the audit's inputs are all reads (`gate-tooling.json`, `package.json`, three workflow files), so the contention is on something one of the four suites writes. A suite that is 36/36 in one order and 33/36 in another is not a gate anyone can trust, and serialising makes it one; finding the writer is the next thing to do, and the honest next step is the same as for the other unidentified flake: capture which suite is mid-write when it happens, not a summary.

**Q0.11 — Contract-safety wave** (§11.2, findings 19–44):

**Item 1 DONE (DB CHECK → classified 4xx).** `apps/api/src/errors/` is now the single error taxonomy. `domain-error.ts` has a `DomainError` with a stable `code` from one `ErrorCode` union and a code→status table, plus `logDetail` for the parts that must never reach a caller; a caller may raise a status into 5xx but not lower a 4xx into a 500, so a client error cannot become an operational alert. `db-errors.ts` maps SQLSTATE to a code **by class**, not by constraint name, so it stays correct as constraints are added: `23514` → `CHECK_CONSTRAINT_VIOLATED` 422, `23505` → `DUPLICATE` 409, `23503` → `VALIDATION_FAILED` 422, `23502` → `MISSING_REQUIRED_FIELD` 400, `22P02` → `INVALID_REQUEST` 400, `40001`/`40P01` → `SERIALIZATION_FAILED` 409 telling the caller to retry, classes 08/53/57 → `DEPENDENCY_UNAVAILABLE` 503, and anything unrecognised → `INTERNAL` 500 with the original kept as `cause`. `boundary.ts` is one `app.onError`/`app.notFound` for the whole app, wired in `index.ts`. `withClassifiedErrors` wraps the execution store and run repository at the composition root so no store method can leak a raw driver error — wrapping method by method is what misses the ones nobody remembers, and it also gives the worker's lease reaper a typed error, which is not an HTTP caller.

  **A real bug surfaced while building this:** Drizzle does not rethrow the `pg` error — it throws its own `Error` whose `cause` carries the code. A classifier reading only the top level classified *every* Drizzle error as `INTERNAL`, which is the bare-500 behaviour the wave exists to remove, and it failed silently because `INTERNAL` is a valid answer. `findSqlState` now walks the `cause` chain, bounded and cycle-safe. A second leak: the constraint name was in `error.message`, which the boundary returns for 4xx, so it reached the client. It now lives in `logDetail` — the log names the constraint, the response does not.

### Q2 — The local reviewer (`pnpm review`) and PR hygiene

**Q2.3 and Q2.4 — the ruleset as data, and the severity policy. DONE as the foundation the rest of Q2 consumes.**

`.github/review-rules/rules.json` declares every rule the automated reviewer can emit: id, category, severity, source, path globs, a rationale, and a fix. Sixteen rules across the plan's thirteen categories, each mapped to one of the eleven reviewer personas in `.github/agents/`, so the human review and the automated review use the same vocabulary — a category without a persona is one nobody owns.

**Why data and not code.** A rule family written as code is discoverable only by reading the emitter, and a rule nobody knows about is a rule nobody trusts. As one file it can be read, argued with, and diffed.

**Q2.4's severity policy is a statement, not a preference.** Only `Blocker` and `Critical` block the merge; `Major` is counted and ratcheted. The reasoning is the plan's own: a solo maintainer cannot absorb a wall of Majors, and a gate that blocks everything gets switched off, taking the two severities that do pass with it. The policy is asserted, not assumed — a test reads `blocksMerge` and requires it to be exactly `['Blocker', 'Critical']`.

**The two drift directions are checked on every run, and they are not symmetric.** An emitter producing a rule id the ruleset does not declare is an **error**: the finding has no severity, and a report whose findings cannot say whether they block cannot decide whether to block a merge. A ruleset declaring a rule no emitter produces is a **warning, not an error**: a declared rule is a statement of intent, and several of the `custom` ones are checked by hand this wave — refusing to load would mean deleting the intent instead of implementing it. That asymmetry is the difference between a hole in the gate and a promise not yet kept.

**Evidence.** `pnpm review:rules` is in `verify`, immediately after `unify:preflight`, because the ruleset is part of the repository's shape and a ruleset that stopped being loadable should fail before any package spends a minute compiling. It has three outcomes, and the third is not a pass: valid, invalid (every problem listed), and **absent** — no ruleset is an error saying what it is for, not an empty review that reports nothing and blocks nothing. **Proven able to fail, three ways:** a three-word rationale fails with `rule eslint.error has no rationale — a rule nobody can question is a rule nobody trusts`; a category remapped to a persona who does not exist fails with `category Bug maps to someone-who-does-not-exist, but the plan's mapping is code-reviewer`; and renaming the file away fails with the "without it the reviewer has no severities and no merge policy" message. `tests/contract/review-ruleset.test.mjs` (13) checks the details, including that the emitters list is **not** derived from the ruleset — deriving it would make the comparison `[]` on both sides forever, and the gate would pass on a ruleset that had lost every rule.

   **A consolidation the ruleset forced, which is the Q0.13 argument again.** Writing the ruleset needed "does this glob match this path", and the format-glob gate from item 4 already had a tested implementation. The first attempt in `ruleset.mjs` built its own, reserving positions with control-character sentinels — which `no-control-regex` refuses, correctly, and which was *also* a second answer to the same question. There is now one: `scripts/review/glob.mjs`, imported by both, supporting only the forms in use and **throwing** on anything else rather than guessing, because a translator that mis-reads its own patterns reports confidently about a set it never computed. The escape the sentinel produced was a `**/` inside a block comment, which closes the comment at `*/` — so the comment now says it in words.

   `review-glob.test.mjs` (12) then tested the translator **directly**, which is what the two consumers could not do between them. It exists because one version of the loop advanced the cursor by the token's length *and* by the loop's own increment: a `**/` ate four positions for a three-character token, the `*` after it was never seen, and `**/*.{ts,tsx}` became `**/` plus a literal dot — a pattern that matches nothing and looks entirely reasonable. The format gate caught it, but reported *"the globs matched nothing in the tree"*, which is a sentence about the tree when the bug is in the glob. **Proven fail-before:** reintroducing the double advance fails **7 of 12**. Two other cases are there for the same reason — a bare `node_modules/` must cover the tree beneath it (matched literally it would only match a file *named* `node_modules`, so an exclusion that did nothing would look like one that worked), and a rule whose globs match nothing is a rule that never fires, which is indistinguishable from a rule nobody implemented.

## 8. Risks

| Risk | Response |
|---|---|
| The quality gate blocks all product progress | Phase the floors: baseline = today's real numbers, ratchet upward per gate; the gate applies to changed code, not to the 27k existing lines |
| Enforcing `exactOptionalPropertyTypes` + `noUncheckedIndexedAccess` cascades | One package per PR, mechanical, no behavior change, review-cheap; a `// @ts-expect-error`-free conversion is itself a quality win |
| Enabling type-aware lint surfaces hundreds of findings | Triage once into `debt-baseline.json` with owners; fix in the same PR that touches the file; never blanket-disable a rule |
| AI waves need a provider that is not available | Contract tests over injected transport are the gate; live smoke is explicitly `not_configured` (D7) |
| OCI images cannot be built in some environments | `unbuilt` is a PR warning, a release blocker; readiness reports the missing runtime instead of degrading |
| Generated tests could inject code | Generated artifacts are untrusted drafts: parse/validate, approve, then execute only inside an isolated runner |
| k6 AGPL obligations | Keep k6 as an external pinned image; the license check produces the deny-list and the decision is recorded in the SLA doc |
| Scope explosion (this plan is very large) | Waves are independently shippable and independently valuable; each has its own gate and can stop after any wave without leaving a broken product |
| The docs/PRD conflict (FastAPI, InfluxDB, Grafana, Allure, Gemini, KAIROS naming) | The repo plus this plan are authoritative: Hono, Postgres-only durable queue, native reporting instead of Allure/Grafana/InfluxDB, Ollama/Kilo, "Automate" naming. ## 13. Review coverage and method

Findings come from a strict read-only review in SonarQube/CodeRabbit style of `apps/api` (§11), `packages/**` (§12), and `apps/web` + `packages/ui` + CI/tooling/scripts + infra + docs + tests (§14). Each finding is recorded as `severity | file:line | category | fix` and mapped to a track task. The full read-only review produced roughly 190 findings; the plan carries every Blocker and Critical plus the grouped Major themes, because a plan is an execution list, not a finding dump.

Verified false: `.github/workflows/{unified-ci,nightly,release-gate}.yml` and 11 files in `.github/agents/` all exist. The rest of that pass was spot-checked line by line and is accurate — the CSS-token bug, the `if (res !== null)` test, the `retry()` URL drift, the missing error boundary, the `compose.dev.yml` healthcheck gap, the compose secrets, and the always-failing `performance-gate` were each independently re-verified in source before being included.
