## Status vocabulary

- `real` — implemented and exercised, with the stated qualification.
- `mock` — a route, response, or UI exists but does not provide the target behavior.
- `missing` — no usable implementation exists in the target.
- `deferred` — intentionally outside the launch scope pending a separate decision.
- `obsolete` — retained only as historical residue and not part of the target product.

A qualification is not a substitute for a status. Split a capability when its pieces have different truth values.

## Evidence rules

- A `real` row must cite both implementation and executable test evidence when the capability is user-visible or security-sensitive.
- A `mock` row must identify the boundary that makes it non-production.
- A `missing`, `deferred`, or `obsolete` row must cite the accepted plan decision or the absent implementation.
- Source repository evidence is provenance only; it does not change the target status.
- Updating this register requires re-running the relevant focused tests and recording the evidence in the Phase change.
