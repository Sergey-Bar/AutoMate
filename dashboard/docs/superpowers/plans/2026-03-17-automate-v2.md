# Automate v2.0 — Implementation Plan

> **For agentic workers:** REQUIRED: Use superpowers:subagent-driven-development (if subagents available) or superpowers:executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Graduate Automate from a v1.0 release into a production-grade v2.0 platform with: all 11 feature-flagged features graduated and gated, auth system with login UI/RBAC, deployment automation, E2E coverage, i18n, mobile responsiveness, observability polish, and operational readiness.

## Critical Findings from Reconnaissance

Before reading the plan, understand these discoveries that shape every sprint:

### Finding 1: Feature Flags Are NOT Enforced Anywhere

The v1 plan built the feature flag **infrastructure** (service, API, store, FeatureGate component, `requireFeature` preHandler) but **never wired it in**:

- `requireFeature()` is exported from `feature-flags.ts` but **never imported** in any route file
- `<FeatureGate>` is exported from `FeatureGate.tsx` but **never used** in any client component
- `useFeature()` is exported from `featureStore.ts` but **never called** in any component

**Impact:** All 11 "v2" features are currently accessible to users in both API and UI despite being "default OFF" in the flag registry. Sprint 1 fixes this before we graduate anything.

### Finding 2: Auth is Server-Only (No Login UI)

- API key auth (generate/validate/revoke) is fully built and tested (32 tests)
- Bearer auth Fastify plugin is registered and working
- REST endpoints exist: `POST/GET/DELETE /api/auth/keys`, `GET /api/auth/status`, `PUT /api/auth/enable`
- **Missing:** No login page, no session management, no client-side route guards, no RBAC/roles, no user accounts

### Finding 3: CI Workflow Triggers on Wrong Branch

`.github/workflows/ci.yml` triggers on `master` but the project uses `main`. CI never runs.

### Finding 4: Observability Is Surprisingly Complete

Already built: Sentry integration, Prometheus `/metrics` endpoint, `/health/live` + `/health/ready` probes, `@fastify/rate-limit` (200 req/min), structured pino logging, graceful shutdown. The plan only adds structured request logging and a docs-site deployment workflow.

- [ ] **Step 3: Implement the plugin**

```typescript
/**
 * Structured request/response logging plugin.
 * Logs every request with method, url, statusCode, responseTime, and userAgent.
 * Skips health endpoints to reduce noise.
 */
import type { FastifyInstance } from 'fastify';

const SKIP_PATHS = new Set(['/health', '/health/live', '/health/ready']);

export async function registerRequestLogger(app: FastifyInstance) {
  app.addHook('onResponse', (req, reply, done) => {
    if (SKIP_PATHS.has(req.url)) {
      done();
      return;
    }

    app.log.info({
      method: req.method,
      url: req.url,
      statusCode: reply.statusCode,
      responseTime: Math.round(reply.elapsedTime),
      userAgent: req.headers['user-agent'] ?? 'unknown',
      contentLength: reply.getHeader('content-length') ?? null,
    }, 'request completed');

    done();
  });
}
```

```typescript
export async function checkAuthStatus(): Promise<{ enabled: boolean; authenticated: boolean }> {
  const res = await fetch('/api/auth/status', { credentials: 'include' });
  if (!res.ok) return { enabled: false, authenticated: false };
  return res.json();
}

export async function login(apiKey: string): Promise<boolean> {
  const res = await fetch('/api/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    credentials: 'include',
    body: JSON.stringify({ apiKey }),
  });
  return res.ok;
}

export async function logout(): Promise<void> {
  await fetch('/api/auth/logout', { method: 'POST', credentials: 'include' });
}
```
